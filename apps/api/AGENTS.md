# Backend working rules

Read the root README, `docs/decisions/0001-local-first-development-with-live-openai.md` (including its amendment), and the relevant feature brief before changing behavior. The backend map and decisions are in `docs/overnight/backend/README.md`.

- PostgreSQL owns accepted trip and packing data. AI returns an editable, unpersisted draft; manual creation validates again. Keep provider calls behind `AiGateway`; normal tests must never contact OpenAI. Do not change application model settings to match the model running an agent task.
- `src/graphql.ts` composes Yoga. `src/graphql/schema.ts` owns the existing SDL and `src/graphql/resolvers.ts` adapts commands. Keep SQL and business policy out of those adapters. Coordinate schema changes with the web owner; use the existing names, nullability and error codes unless a product change requires otherwise.
- `src/trips/*-service.ts` owns transactions and itinerary commands. `inputs.ts` validates shapes and transport endpoints; `policy.ts` holds pure date rules; `transactions.ts` holds trip locks, revisions and chronology writes. Direct Drizzle queries here are intentional; avoid generic repositories and wrapper classes without a concrete need.
- Every accepted itinerary edit locks its parent trip before child writes, checks the supplied revision, and increments it once. Return the changed view inside that same transaction. Never replace a transaction's `tx` with the pool database. Execute statements on one transaction client sequentially. Trip queries use a read-only repeatable-read snapshot.
- Packing mutations lock in the order trip (when relevant), profile, plan. Its fixed local profile is not account authentication. Preserve separate library/plan revisions, ownership checks and manual packing overrides.
- `src/trip-creation.ts` is a compatibility entry point. Schemas, calendar interpretation, evidence verification and draft assembly live in `src/trip-creation/`. Keep these pure and independently testable. Treat quoted model evidence as untrusted. Preserve unresolved/ambiguous fields rather than silently choosing dates or cities.
- Expose known `AppError`/validation failures through `src/graphql/errors.ts`; leave unexpected errors masked, including in development. Never put SQL, credentials, raw provider responses or trip prompts into public error extensions or logs.
- Preserve existing `drizzle/` migrations. Generate and review additive migrations for actual schema changes; never rewrite history or reset a shared database. `pnpm test:postgres` rebuilds its target test schemas: use a dedicated disposable local `tripdock_test`, explicitly set `TEST_DATABASE_URL`, and verify the target first.
- Run `pnpm check` from the repository root. For transaction/constraint changes also run `pnpm test:postgres` on isolated data. pg-mem does not prove concurrent locking or PostgreSQL constraint behavior. Add behavioral regressions for meaningful changes; avoid source-text tests that merely restate implementation.
- Keep the service local-only. Deployment, authentication, shared-user authorization, destructive data work and billed provider checks require task-specific authorization. Reversible implementation and deterministic local verification do not need routine reconfirmation.
